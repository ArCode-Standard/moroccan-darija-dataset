# سياسة جمع موارد الدارجة المغربية

## 1. الغرض

تنظم هذه السياسة جمع الموارد لمشروع Moroccan Darija Digital Language Resources، بنمط هجين يجمع الملاحظة والمساهمة البشرية مع المعالجة الآلية للمواد التي يملك المشروع حق معالجتها.

**المبدأ:** نجمع الموارد اللغوية، لا بيانات الأشخاص. لا يتتبع المشروع المستخدمين ولا ينشئ ملفات تعريف عنهم.

## 2. مسارا العمل

### أ. الجمع اليدوي
- يسجل الباحث كلمة أو تعبيراً لاحظه أثناء استخدام مصدر يمكن الوصول إليه بصورة مشروعة.
- لا ينسخ المحادثة أو الفقرة أو المنشور الأصلي لمجرد تسجيل المفردة.
- يكتب وصفاً دلالياً مستقلاً وموجزاً، ويحتفظ بمرجع داخلي غير شخصي بالقدر اللازم للتدقيق.
- لا ينسب اللفظة إلى منطقة أو فئة اجتماعية بناءً على ملاحظة منفردة.

### ب. الجمع بمساعدة الأدوات
- يقتصر الاستيراد والمعالجة الآلية على ملفات يملك المشروع حق معالجتها أو مصادر/واجهات تسمح شروطها بذلك صراحة.
- لا تُستخدم أدوات scraping لتجاوز قيود المنصات أو تسجيل الدخول أو الحواجز التقنية.
- لا تُجمع الرسائل الخاصة أو بيانات الحسابات أو قوائم الأصدقاء أو بيانات النشاط.
- تمر جميع المرشحات الناتجة عن الأدوات بمراجعة بشرية قبل اعتمادها.

## 3. نطاق الاستخدام

يفصل المشروع بين:
1. **الاكتشاف المعجمي:** تسجيل مفردة أو تعبير وملاحظة لغوية مستقلة.
2. **المدونة النصية (Corpus):** الاحتفاظ بنصوص أو جمل أو تفريغات صوتية وفق إذن وحقوق محددة.
3. **النشر:** إعادة توزيع المورد وفق ترخيصه وأدلة الحقوق.
4. **التدريب:** استخدام مستقل يتطلب تحققاً صريحاً من الإذن.
5. **الاستخدام التجاري:** لا يستنتج من إتاحة المصدر أو السماح بالاكتشاف.

الإذن بالاكتشاف لا يعني الإذن بالتخزين أو إعادة التوزيع أو التدريب أو الاستخدام التجاري.

## 4. الخصوصية وتقليل البيانات

لا يجمع المشروع:
- أسماء الحسابات أو الصور الشخصية أو أرقام الهواتف أو عناوين البريد.
- معرفات الأجهزة أو عناوين IP أو بيانات الموقع الدقيق.
- الرسائل الخاصة أو محتوى المجموعات المغلقة.
- سجلات نشاط المستخدمين أو بيانات التتبع والسلوك.

تُحذف البيانات الشخصية العرضية من المساهمات قبل إدخالها إلى موارد المشروع. لا تُخزن النصوص الأصلية إذا لم تكن ضرورية ومصرحاً بها.

## 5. قواعد المصادر

- ظهور المحتوى علناً لا يمنح تلقائياً حق نسخه أو إعادة توزيعه.
- شروط كل منصة وترخيص كل مادة يقيّمان على حدة.
- لا تُجمع مواد من منصة إذا كانت شروطها تمنع طريقة الجمع المقترحة.
- يمكن طلب مساهمات لغوية طوعية أو إذن مكتوب من صاحب الحق.
- لا تنشر أسماء الأعمال أو المؤلفين أو المنصات في الواجهة العامة إلا عند الحاجة وبما يتفق مع الحقوق والخصوصية؛ مع الاحتفاظ بتوثيق داخلي مناسب.

## 6. دورة حياة المرشح

`discovered -> candidate -> in_review -> verified | needs_correction | rejected`

حالة الحقوق مستقلة عن الحالة اللغوية:
`pending_verification | cleared | restricted | unknown | excluded`

لا يعني التحقق اللغوي أن الحقوق صارت واضحة، ولا يعني اكتمال الحقوق أن اللفظة صحيحة لغوياً.

## 7. الحد الأدنى لسجل الاكتشاف

- معرّف المرشح.
- الصيغة الأصلية كما لوحظت.
- نوع الوحدة إن أمكن.
- معنى مقترح مع وسم أنه غير معتمد.
- نوع المصدر وطريقة الجمع.
- تاريخ الملاحظة.
- مرجع داخلي غير شخصي عند الحاجة.
- حالة الحقوق لكل غرض.
- حالة المراجعة.

لا تُخترع مصادر أو تواريخ أو صيغ بديلة. تُحفظ تهجئة Arabizi الأصلية وتُراجع الاختلافات دون دمج آلي.

## 8. بوابة النشر

لا ينتقل أي نص أو مثال أو ملف صوتي إلى الإصدار العام إلا بعد:
- مراجعة الخصوصية.
- التحقق من حقوق إعادة التوزيع.
- التحقق من الترخيص وشروط الإسناد.
- مراجعة لغوية مناسبة.
- نجاح التحقق البنيوي.

تُحفظ المواد المقيّدة أو غير المحسومة خارج حزمة النشر العامة.

## 9. مراجعة السياسة

تراجع هذه السياسة عند إضافة مصدر جديد أو تغيير طريقة الجمع أو توسيع نطاق الاستخدام. تسجل التغييرات في Git مع سببها وتاريخها.
