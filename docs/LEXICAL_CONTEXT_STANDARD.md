# معيار إثراء السياق والمعنى للمدخل المعجمي

## 1. الهدف

يضيف هذا المعيار المعلومات اللازمة لفهم استعمال التعبير المغربي، بدلاً من الاكتفاء بالكلمة ومقابلها بالفصحى والفرنسية. يهدف إلى دعم البحث المعجمي، والتحليل اللغوي، وبناء موارد NLP قابلة للتقييم.

لا يجوز اختلاق سياق أو مثال أو معنى لإكمال الحقول. استخدم حالة نقص صريحة إلى حين مراجعة متحدث أو محرر مؤهل.

## 2. نموذج البيانات المقترح

تبقى الحقول الأساسية الحالية كما هي. وتضاف حقول اختيارية تدريجياً، مع اعتماد بنية `senses` لتسجيل تعدد المعاني:

| الحقل | النوع | الغرض |
|---|---|---|
| `entry_type` | enum | نوع الوحدة: كلمة أو تعبير أو جملة أو مثل أو سؤال أو صيغة محادثية |
| `part_of_speech` | string/enum | نوع الكلمة: اسم، فعل، صفة، ظرف، أداة، ضمير، حرف، أو غير ذلك |
| `context` | string | شرح موجز لمجال أو موقف الاستعمال |
| `register` | enum | محايد، رسمي، غير رسمي، سوقي، أدبي، ديني، أو غير معروف |
| `region` | string[] | مناطق الاستعمال المدعومة بدليل؛ لا تستخدم التخمين |
| `senses` | array | المعاني المستقلة للمدخل |
| `examples` | array | أمثلة طبيعية مع ترجمتها ومصدرها |
| `usage_notes` | string | ملاحظات تداولية أو صرفية أو تركيبية |
| `review` | object | حالة المراجعة البشرية ودليلها |

### بنية المعنى المقترحة

كل عنصر في `senses` يمثل معنى واحداً، ويحتوي على:

- `sense_id`: معرّف ثابت للمعنى داخل المدخل.
- `definition_ar`: شرح واضح بالعربية، ويفضل أن يوضح المعنى لا أن يكرر المقابل.
- `definition_darija`: شرح بالدارجة إن أمكن.
- `fusha_ar`: مقابل تقريبي بالفصحى لهذا المعنى تحديداً.
- `fr`: مقابل فرنسي لهذا المعنى تحديداً.
- `domain`: مجال الاستعمال عند الحاجة، مثل الطعام أو العمل أو التقنية.
- `register`: مستوى اللغة إذا اختلف عن مستوى المدخل العام.
- `usage_label`: حرفي، مجازي، اصطلاحي، تهكمي، ملطف، أو غير ذلك.
- `region`: نطاق جغرافي موثق لهذا المعنى.
- `examples`: أمثلة تخص هذا المعنى.

### بنية المثال المقترحة

كل مثال يحتوي على:

- `darija_ar`: الجملة بالخط العربي.
- `darija_latin`: كتابة لاتينية كما قدمها المصدر/المساهم؛ لا تفرض صيغة موحدة.
- `translation_ar`: شرح أو ترجمة بالفصحى.
- `translation_fr`: ترجمة فرنسية عند توفرها.
- `source_id`: مرجع إلى مصدر المثال في سجل المصادر.
- `is_attested`: هل المثال موثق من استعمال فعلي أم منشأ لأغراض التوضيح؟
- `notes`: ملاحظات عند الحاجة.

لا تنشر مثالاً من محادثة خاصة دون موافقة مناسبة وإزالة أي معلومات تعريفية. يجب أن يكون لكل مثال مصدر وحقوق مستقلان عندما لا يكون من إنشاء المساهم بموافقة واضحة.

## 3. تصنيف نوع الوحدة

استخدم قيمة واحدة دقيقة:

- `word`: مفردة.
- `expression`: تركيب ثابت أو شبه ثابت.
- `sentence`: جملة كاملة.
- `proverb`: مثل أو حكمة متداولة.
- `question`: صيغة استفهامية.
- `conversational`: صيغة تواصلية/تداولية قصيرة.
- `unknown`: لم يحسم النوع بعد.

يمكن إضافة `part_of_speech` للكلمات فقط. لا تفرض نوعاً صرفياً على الأمثال والجمل.

## 4. تعدد المعاني

- أنشئ معنى مستقلاً فقط عندما يختلف المعنى، لا لمجرد وجود ترجمات متعددة.
- اربط كل ترجمة ومثال بالمعنى الذي يخصه.
- ميّز بين المعنى الحرفي والمجازي والاستعمال الاصطلاحي.
- لا تدمج اختلافات جهوية أو اجتماعية في معنى واحد إذا كان الفرق مؤثراً.
- إذا لم يُحسم المعنى، استخدم `sense_status: "needs_review"` أو اترك المعنى غير محسوم؛ لا تخترع تعريفاً.
- لا تفترض أن كل كلمة لها معنى واحد أو أن كل سجل يحتاج إلى أكثر من معنى.

## 5. التوثيق الجهوي والاجتماعي

- لا تضع اسم مدينة أو جهة لمجرد أن المراجع منها.
- سجل المنطقة فقط عندما يقدم المصدر دليلاً على الاستعمال أو عندما يؤكدها أكثر من متحدث مستقل وفق قواعد المشروع.
- ميّز بين مكان جمع المثال ومكان شيوع التعبير.
- لا تحول اختلافاً فردياً في النطق أو الكتابة إلى تصنيف جهوي.
- استخدم `unknown` عند غياب الدليل، ولا تستخدم `Morocco` كقيمة افتراضية لكل سجل.

## 6. أمثلة توضيحية للهيكل (ليست بيانات معجمية معتمدة)

```json
{
  "id": 0000,
  "entry_type": "word",
  "part_of_speech": "unknown",
  "context": "",
  "register": "unknown",
  "region": [],
  "senses": [
    {
      "sense_id": "0000-1",
      "definition_ar": "",
      "definition_darija": "",
      "fusha_ar": "",
      "fr": "",
      "usage_label": "unknown",
      "examples": [
        {
          "darija_ar": "",
          "darija_latin": "",
          "translation_ar": "",
          "translation_fr": "",
          "source_id": "",
          "is_attested": false
        }
      ]
    }
  ],
  "usage_notes": "",
  "review": {
    "status": "pending"
  }
}
```

هذا المثال قالب بنيوي فقط. لا تنسخ السجل إلى بيانات الإنتاج قبل تعبئته بمعلومات حقيقية ومراجعتها.

## 7. سياسة الكتابة اللاتينية

تُحفظ صيغة المساهم الأصلية كما هي. يمكن تسجيل عدة صيغ لاتينية مقبولة للمدخل أو للمثال، ولا يفرض المعيار lowercase أو تهجئة واحدة. لا تدمج السجلات اعتماداً على تشابه Arabizi وحده. يجب ربط كل صيغة بمصدرها أو بمراجعة لغوية موثقة.

## 8. درجات اكتمال السياق

استخدم مؤشرات الجودة التالية في تقارير التدقيق، لا كبديل عن المراجعة:

- `L0`: الحقول الأساسية فقط.
- `L1`: نوع الوحدة وسياق موجز.
- `L2`: معنى/تعريف واضح ومقابل مرتبط به.
- `L3`: مثال واحد موثق الحقوق ومترجم.
- `L4`: مراجعة بشرية للمعنى والاستعمال، مع توثيق التنوع الجهوي أو register عند انطباقه.

لا يعني بلوغ مستوى أعلى أن السجل صحيح تلقائياً؛ يجب الاحتفاظ بحالة المراجعة ودليلها.

## 9. سير المراجعة

1. يراجع المساهم نوع الوحدة والتهجئة.
2. يحدد معنى واحداً أو أكثر مع تعريف مستقل لكل معنى.
3. يضيف مثالاً طبيعياً واحداً على الأقل عندما يكون ذلك مفيداً ومتاحاً.
4. يرفق مصدر المثال وحقوقه.
5. يراجع متحدث/محرر آخر طبيعية التعبير ودقته وسياقه.
6. تسجل المراجعة بمعرّف مستعار وتاريخ وقرار وسبب.
7. لا تتحول الحالة إلى `reviewed` بمجرد نجاح الفحص الآلي.

## 10. سياسة الانتقال للبيانات الحالية

لا تُثرِ جميع السجلات آلياً اعتماداً على ترجمة واحدة. ابدأ بدفعات صغيرة ومتوازنة من الفئات، واحتفظ بقيم الحقول الأصلية. لا تضف أمثلة اصطناعية على أنها استعمالات موثقة. يمكن إضافة أمثلة تحريرية منشأة للتوضيح فقط إذا وُسمت بوضوح `is_attested: false`، وراجعتها جهة لغوية، ووُثقت حقوقها.

## 11. معيار قبول سجل محسّن

يُقبل السجل المحسّن عندما:
- تكون الوحدة مصنفة تصنيفاً معقولاً.
- يكون لكل معنى تعريف مستقل ومقابل مناسب عند الحاجة.
- لا يُخلط بين المعنى والترجمة الحرفية.
- يكون السياق والمثال طبيعيين ومفهومين.
- يكون مصدر المثال وحقوقه معروفين أو موصوفين بوضوح.
- لا توجد ادعاءات جهوية بلا دليل.
- تسجل المراجعة البشرية وقرارها.
