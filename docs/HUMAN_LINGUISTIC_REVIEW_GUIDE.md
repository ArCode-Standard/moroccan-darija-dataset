# دليل المراجعة اللغوية البشرية

## الغرض

تنظيم مراجعة المعجم على دفعات من 50 مدخلاً. ملف الدفعة لا يمثل حكماً لغوياً؛ كل قرار يبقى فارغاً إلى أن يراجعه شخص ويضيف دليلاً أو ملاحظة قابلة للتتبع.

## محاور المراجعة

1. **دقة المعنى:** هل المقابل بالفصحى والفرنسية يعكس المعنى المقصود في الدارجة؟ هل توجد معانٍ متعددة تستلزم سجلات senses منفصلة؟
2. **الرسم العربي:** هل الصيغة مكتوبة كما يستعملها متحدثون مغاربة؟ لا تفرض توحيداً إملائياً غير مبرر.
3. **الكتابة اللاتينية:** احتفظ بالصيغة المقدمة، وسجل البدائل الموثقة دون اعتبار اختلاف Arabizi خطأ تلقائياً.
4. **نوع الوحدة والكلمة:** ميّز بين كلمة، تعبير، سؤال، جملة، مثل، وصيغة محادثية. لا تخمن التصنيف عند غياب السياق.
5. **السياق والسجل:** وثّق الاستعمال والسجل اللغوي عند وجود دليل. لا تخترع أمثلة.
6. **النطاق الجهوي:** لا تنسب اللفظة إلى منطقة أو إلى عموم المغرب بناءً على ملاحظة واحدة.
7. **الأدلة:** أضف مرجعاً يمكن للمراجع التالي التحقق منه، مع مراعاة سياسة الحقوق والخصوصية.

## حالات المراجعة

- `pending`: لم تبدأ المراجعة.
- `in_review`: المراجع يعمل على السجل.
- `reviewed`: تمت مراجعة الحقول المحددة مع تسجيل المراجع والتاريخ والأدلة.
- `needs_correction`: يلزم تعديل مع توضيح السبب.
- `rejected`: لا يصلح السجل بصيغته الحالية، مع توثيق السبب.

لا تستخدم `reviewed` لمجرد قراءة المدخل. يجب أن تكون الحقول التي تمت مراجعتها واضحة، وأن تبقى الحقول غير المحسومة غير معتمدة.

## فصل المراجعة اللغوية عن الحقوق

المراجعة اللغوية لا تمنح حق إعادة التوزيع أو التدريب أو الاستخدام التجاري. حالة الحقوق تبقى في `data/sources.json` وحقول `provenance` وفق `docs/DATA_PROVENANCE_AND_RIGHTS.md`.

## بدء العمل

ابدأ بـ `data/review/lexical-review-batch-01.json` (المعرفات 1–50). لا تملأ هوية المراجع أو التاريخ أو القرارات آلياً. بعد مراجعة الدفعة، حدّث السجلات بأدلة المراجع ثم شغّل:

```bash
python scripts/validate_dataset.py --sources data/sources.json
python -m unittest discover -s tests -v
```

بوابة `--strict-public` مخصصة فقط للسجلات التي اكتملت حقوق إعادة توزيعها وموافقة نشرها؛ لا تستخدمها لإعلان اكتمال المراجعة اللغوية.
