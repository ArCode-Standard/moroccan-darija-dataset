لم يظهر تكرار حرفي مطابق في `darija_latin`. لكن ظهر تصادم واحد عند تحويل الكتابة إلى lowercase:

## 4. مشكلة غياب السياق

لا يحتوي أي من السجلات الـ921 على حقول `context` أو `entry_type` أو `region` أو `register` أو `provenance` أو `review`.

**الأثر اللغوي:** لا يمكن للمعجم وحده توثيق تعدد المعاني أو الاستعمال التداولي أو الفرق بين المناطق أو مستويات اللغة. وقد تكون ترجمة واحدة بالفصحى أو الفرنسية غير كافية لشرح المدخل.

**قرار التصميم:** تُحفظ الأمثلة والمعاني السياقية في ملف مستقل `data/context-examples.json`، وترتبط بالسجل الأساسي من خلال `entry_id`. هذا يسمح بوجود عدة معانٍ وأمثلة للمدخل نفسه، ويحافظ على خفة الملف المعجمي الأساسي. أُضيف مخطط مستقل لهذا الملف في `data/context-schema.json`.

يبدأ ملف السياق الحالي فارغاً (`examples_count = 0`). لم تُنشأ أمثلة مصطنعة أو تُنسب إلى متحدثين دون مصدر.

## 5. تفعيل JSON Schema Draft 2020-12

كان المدقق السابق ينفذ فحوصاً مخصصة فقط، ولا يطبق `data/schema.json` فعلياً. أُضيف التنفيذ والاختبارات التالية إلى فرع التحديث؛ ويجب اعتماد نتيجة GitHub Actions بعد تشغيلها قبل اعتبار الاختبارات منفذة بنجاح:
- الاعتماد على حزمة `jsonschema` وتثبيتها من `requirements.txt`.
- التحقق باستخدام `Draft202012Validator`.
- التحقق من صيغ الحقول المدعومة بواسطة `FormatChecker`.
- استمرار فحوص المشروع المخصصة، مثل تفرد المعرّفات وتطابق الأعداد.
- التحقق من مخطط ملف السياق المستقل.
- التحقق من أن كل `entry_id` في الأمثلة السياقية يشير إلى مدخل موجود.
- اختبارات للمخطط نفسه، ولرفض الخصائص غير المعرفة، وللروابط بين الملفين.
- سير عمل GitHub Actions لتشغيل المدقق والاختبارات.

ملاحظة تقنية: JSON Schema يتحقق من أنواع الحقول وقواعدها، لكنه لا يقارن تلقائياً عدد عناصر المصفوفة بقيمة حقل آخر مثل `meta.entries_count`. لذلك تبقى هذه المقارنات ضمن الفحوص المخصصة.

## 6. مسائل لم يحسمها التدقيق

### Q-01 — غموض الرمز 3
تصف بيانات التعريف `3` بأنه قد يمثل «ع / ء»، بينما تصفه الملاحظات بأنه يمثل «ع» فقط. يلزم قرار تحريري موحد وأمثلة قبل تعديل البيانات.

### Q-02 — تعدد تمثيل الأصوات
قد يُكتب غ بأكثر من طريقة مثل `gh` و`4`. لا تفرض lowercase ولا تطبيعاً يحذف الفروق. احتفظ بالصيغ الأصلية، وأضف البدائل بوصفها بدائل لا سجلات مكررة.

### Q-03 — المصدر والحقوق
لا يوجد `provenance` على مستوى السجل. لا يمكن تأكيد المصدر أو صاحب الحقوق أو إذن إعادة التوزيع أو التدريب أو الاستخدام التجاري لكل مفردة. يجب تسجيل `unknown` عند غياب الإثبات وعدم اعتبار ترخيص المستودع دليلاً على حقوق كل مادة خارجية.

### Q-04 — المراجعة البشرية
لا توجد حالة مراجعة موثقة في السجلات الحالية. لا ينبغي وصف المجموعة بأنها مدققة لغوياً.
